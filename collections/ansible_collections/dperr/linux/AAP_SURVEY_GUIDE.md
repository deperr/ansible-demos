## config_ubuntu_mirrors Survey

Configure Ubuntu clients to use internal APT mirrors.

### Survey Variables Summary

| Variable | Type | Required | Default |
|----------|------|----------|---------|
| `mirror_server_hostname` | Text | Yes | `ubuntu-svr-01.dperrone.dev` |
| `config_client_mirrors_profiles` | Multiple Choice (multi) | Yes | `[]` |
| `config_client_mirrors_external_sources_enabled` | Multiple Choice | No | `false` |

### Survey Question 1: Mirror Server Hostname

```yaml
Variable Name: mirror_server_hostname
Question: What is the hostname or IP address of your internal mirror server?
Description: FQDN or IP address where the APT mirror server is hosted
Answer Type: Text
Default Answer: ubuntu-svr-01.dperrone.dev
Required: Yes
```

### Survey Question 2: Mirror Profiles to Configure

```yaml
Variable Name: config_client_mirrors_profiles
Question: Which mirror profiles should be configured on the client?
Description: Select one or more mirror types to configure
Answer Type: Multiple Choice (allow multiple selections)
Required: Yes
Choices:
  - ubuntu
  - docker_ce
```

**AAP Format (YAML List):**
```yaml
- choice: ubuntu
- choice: docker_ce
```

### Survey Question 3: Enable Air-Gap Mode

```yaml
Variable Name: config_client_mirrors_external_sources_enabled
Question: Should external APT sources be removed? (Air-gap mode)
Description: When enabled, all external package sources will be removed, locking the system to internal mirrors only. This is difficult to reverse.
Answer Type: Multiple Choice
Required: No
Default Answer: false
Choices:
  - label: "No - Keep external sources available (default)"
    value: false
  - label: "Yes - Remove all external sources (air-gap mode)"
    value: true
```

**AAP Format (YAML List):**
```yaml
- choice: "false"
- choice: "true"
```

### Survey Question 4: Create tarball of mirror

```yaml
Variable Name: capt_mirror_server_create_export_tarball
Question: Create tarball of mirror
Description: Create initial tarball of mirror
Answer Type: Multiple Choice
Required: Yes
Default Answer: false
Choices:
  - value: false
  - value: true
```

**AAP Format (YAML List):**
```yaml
- choice: "false"
- choice: "true"
```

### Example Extra Variables (Generated by Survey)

```yaml
mirror_server_hostname: mirror.corp.local
config_client_mirrors_profiles:
  - ubuntu
  - docker_ce
config_client_mirrors_external_sources_enabled: false
```

## config_ubuntu_server Survey

Configure an Ubuntu server as an APT mirror using apt-mirror and nginx.

### Survey Variables Summary

| Variable | Type | Required | Default |
|----------|------|----------|---------|
| `apt_mirror_server_profile` | Multiple Choice | Yes | `docker_ce` |
| `apt_mirror_server_upstream` | Text | Yes | `https://download.docker.com/linux/ubuntu` |
| `apt_mirror_server_codenames` | Multiple Choice (multi) | Yes | `[noble]` |
| `apt_mirror_server_architectures` | Multiple Choice (multi) | Yes | `[amd64]` |
| `apt_mirror_server_run_initial_sync` | Multiple Choice | No | `false` |
| `apt_mirror_server_create_export_tarball` | Multiple Choice | No | `false` |

### Survey Question 1: Mirror Profile Type

```yaml
Variable Name: apt_mirror_server_profile
Question: Which repository profile should this mirror server host?
Description: Choose the type of repository to mirror. Docker CE is smaller and faster for testing.
Answer Type: Multiple Choice
Required: Yes
Default Answer: docker_ce
Choices:
  - label: "Docker CE - Docker Community Edition packages (5-10 GB, quick sync)"
    value: docker_ce
  - label: "Ubuntu OS - Full Ubuntu archive (50+ GB per codename, slow sync)"
    value: ubuntu
```

**AAP Format (YAML List):**
```yaml
- choice: docker_ce
- choice: ubuntu
```

### Survey Question 2: Upstream Repository URL

```yaml
Variable Name: apt_mirror_server_upstream
Question: What is the upstream repository URL to mirror?
Description: The base URL of the repository to sync from. Must include the full path.
Answer Type: Text
Required: Yes
Default Answer: https://download.docker.com/linux/ubuntu
```

**Common Values:**
- Docker CE: `https://download.docker.com/linux/ubuntu`
- Ubuntu US: `http://us.archive.ubuntu.com/ubuntu`
- Ubuntu Main: `http://archive.ubuntu.com/ubuntu`

### Survey Question 3: Ubuntu Release Codenames

```yaml
  - label: "focal - Ubuntu 20.04 LTS (April 2025 EOL)"
    value: focal

    value: jammy
  - label: "noble - Ubuntu 24.04 LTS (April 2029 EOL)"
    value: noble
```

**AAP Format (YAML List):**
```yaml
- choice: focal
- choice: jammy
- choice: noble
```

## Combined Workflow Surveys

### Workflow 1: Complete Mirror Infrastructure Setup

This workflow configures both the mirror server AND client systems in one job.

#### Survey for Combined Setup

```yaml
# Survey Variables
mirror_server_hostname: mirror.example.com

# Server configuration
apt_mirror_server_profile: docker_ce
apt_mirror_server_upstream: https://download.docker.com/linux/ubuntu
apt_mirror_server_codenames: [noble]
apt_mirror_server_architectures: [amd64]
apt_mirror_server_run_initial_sync: true

# Client configuration
config_client_mirrors_profiles:
  - docker_ce
config_client_mirrors_external_sources_enabled: false
```

#### Playbook Structure

```yaml
---
- name: Configure APT mirror server
  hosts: mirror_servers
  become: true
  roles:
    - role: dperr.linux.config_ubuntu_server
      vars:
        apt_mirror_server_profile: "{{ apt_mirror_server_profile }}"
        apt_mirror_server_upstream: "{{ apt_mirror_server_upstream }}"
        apt_mirror_server_codenames: "{{ apt_mirror_server_codenames }}"
        apt_mirror_server_architectures: "{{ apt_mirror_server_architectures }}"
        apt_mirror_server_run_initial_sync: "{{ apt_mirror_server_run_initial_sync }}"

- name: Configure clients to use mirror
  hosts: ubuntu_clients
  become: true
  roles:
    - role: dperr.linux.config_ubuntu_mirrors
      vars:
        mirror_server_hostname: "{{ mirror_server_hostname }}"
        config_client_mirrors_profiles: "{{ config_client_mirrors_profiles }}"
        config_client_mirrors_external_sources_enabled: "{{ config_client_mirrors_external_sources_enabled }}"
```

## AAP Survey Best Practices

### Variable Naming

- Use descriptive, namespaced variable names
- Role-specific prefix prevents conflicts (`apt_mirror_server_`, `config_client_mirrors_`)
- Use underscores for readability

### Question Design

1. **Question Text**: Clear, concise, avoids technical jargon
2. **Description**: Provide context, warnings, and examples
3. **Defaults**: Set safe, sensible defaults
4. **Required**: Only mark truly essential variables as required

### Choice Labels

- Use human-friendly labels with value explanations
- Include resource impact (disk space, time) in descriptions
- Provide defaults labeled as "(recommended)" when appropriate

### Multi-Select Lists

For AAP surveys with multiple selections, the variable value will be a YAML list:

```yaml
# Survey allows selecting multiple codenames
apt_mirror_server_codenames:
  - jammy
  - noble
```

Ensure your playbook/role expects a list data type for these variables.

## Troubleshooting Survey Issues

### Lists Not Parsing Correctly

**Problem**: Survey creates string instead of list

**Solution**: In AAP survey configuration, ensure "Answer Type" is "Multiple Choice (multiple select)"

### Boolean Values as Strings

**Problem**: Boolean appears as string `"true"` instead of `true`

**Solution**: Use Jinja2 filter in playbook:
```yaml
config_client_mirrors_external_sources_enabled: "{{ config_client_mirrors_external_sources_enabled | bool }}"
```

### Undefined Variables

**Problem**: Optional survey variables not provided

**Solution**: Use default filters:
```yaml
apt_mirror_server_create_export_tarball: "{{ apt_mirror_server_create_export_tarball | default(false) }}"
```
